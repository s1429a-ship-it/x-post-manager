# バズ動画 分析フレームワーク

`CLAUDE.md`（自律エージェントの分析STEP）と `index.html`（手動プロンプト生成アプリ）が共通で参照する、単一の分析フレームワーク。どちらかだけを更新して内容がズレることを防ぐため、観点を追加・変更する場合はこのファイルを起点にする。

## 人格（persona）

書き手は18年の接客経験と3人の子育て経験を持つ母親目線の発信者。フォロワー数ではなく「なぜこの動画が刺さったのか」を分析し、母親・働く女性が「自分でもできそう」と思える信頼を積み上げることを目的とする。

## 分析の4観点

「動画の特徴を説明して終わり」にせず、必ず次の流れで掘り下げる。

```
動画で起きたこと
  ↓
なぜ起きた？
  ↓
視聴者の頭の中で何が起きた？
  ↓
どんな感情が生まれた？
  ↓
どんな行動につながる？
  ↓
どう再現する？
```

### ① なぜ指が止まったのか
視聴者が最初の瞬間に何を認識し、「何これ？」「どうなるの？」と思った理由。冒頭の引き、構成の意外性。

### ② バズの本質（なぜ可愛い・面白い・気になると思ったのか）
視聴者の感情がどう動いたかを、次の3つの切り口で整理する。
- 言語ゼロ設計（テキストなし、音や映像だけで伝わる工夫）
- 感情を代弁する構造（映像が先に「気持ち」を言っているか）
- 完視聴率を高める工夫（離脱させない仕掛け、意外性・ギャップ・オチ）

### ③ なぜ最後まで見たのか／実装面
完視聴につながる構造の分析と、使ったと思われるツール・プロンプト・コストと手間・実装のコツを、真似しやすい粒度で整理する。

### ④ なぜ共有・保存したくなるのか／ビジネス視点
視聴後の行動（共有・保存・フォロー）につながる要素の分析と、自分が同じ手法で発信するなら何を優先するか、時間制約のある読者でも実現できる方法を提案する。

## 保存される条件（4つの欲求）

動画に限らず、リスト・まとめ系のコンテンツ（例:「〇〇な50サイト」）が保存される理由は、情報量の多さではなく、読み手にとって「あとで開きたくなる理由」がいくつあるかで決まる。中身への欲求は主に次の4つに分解できる。

- **眺めたい**（見ているだけで満足する）
- **覗きたい**（中身を確認したい、好奇心）
- **調べたい**（実用のために深掘りしたい）
- **触れたい**（実際に使ってみたい）

同じリストでも、どの欲求が刺さるかは読み手によって違う。だからこそ、欲求の種類をカバーするほど「保存する理由」が読み手の数だけ増える。成果物作成・品質チェックの際は、情報量を増やすことより、この4つの欲求のうち何個を満たしているかを確認する。

## 指標の読み方

数字を見るときは、表示回数やいいね数の絶対値だけでなく、比率にも注目する。

- **いいね:リポスト比率**: 通常は5:1前後が多い。この比率がほぼ1:1に近づく投稿は、「共感して終わり」ではなく「保存して自分のタイムラインに流したい」という拡散動機が強いサイン。エンゲージメント率が低めでも、この比率が偏っていれば評価を上げてよい。
- **同じツール・同じ手法でも結果は対極になりうる**。ツール自体の新しさや性能ではなく、キャプションでの翻訳（視聴者向けの言葉になっているか）とキャラクター・テーマの説得力が数字を左右する。比較できる事例が2つ以上ある場合は、単独の手法紹介より「同じツールで結果が分かれた理由」を並べた比較解説の方が説得力を持つ。

## 再現企画への変換

単なる感想で終わらせず、「何を真似すれば再現できるのか」まで具体化する。①〜④の分析結果を、他の動画にも応用できる再現可能な構造に変換する。

## 成果物テンプレート

### Xスレッド構成
①〜④の4ブロックで構成し、各ブロックは短い文と改行でスマホで読みやすくする。読み手が「なぜこの動画が伸びたのか分かった」→「自分でも作れそう」→「もっと知りたい」となる流れを優先する。

### LINE誘導文
Xスレッドの最後に続けて使う。売り込み感を抑え、「スキマ時間で学べる環境」として自然に登録を促し、最後にリンクを入れる。

## 品質チェック観点

完成した文章について、次を確認し、問題があれば自分で修正する。
- 冒頭が弱くないか
- 説明が長すぎないか
- 抽象論になっていないか
- 実践方法まで落ちているか
- 読者にとって保存する価値があるか（「保存される条件（4つの欲求）」のうち何個を満たしているか）
- 宣伝臭が強すぎないか
- Xで読みやすいか
